# 构建指南

本文档说明如何从源码产出可安装的签名 APK。整体分三阶段，分别在不同环境执行。

## 0. 准备

| 环境 | 用途 | 所需软件 |
|---|---|---|
| x86_64 Ubuntu（构建机） | 交叉生成 arm64 RootFS | debootstrap、qemu-user-static、zstd、git、tar |
| 任意（含 Windows/Linux/macOS） | 编译 APK | JDK 17、Android SDK（compileSdk 35） |

安装 Ubuntu 依赖：

```bash
sudo apt update
sudo apt install -y debootstrap qemu-user-static zstd git tar
```

> 交叉 chroot 依赖内核 binfmt_misc 注册 `qemu-aarch64-static`（qemu-user-static 包通常已自动注册）。
> 若用 Docker，先执行 `docker run --rm --privileged tonistiigi/binfmt --install arm64`。

## 1. 构建 RootFS

```bash
# 可选：设置 DSH 仓库地址与版本
export DSH_REPO="https://github.com/your-org/your-dsh-fork.git"   # 替换为实际地址
export DSH_VERSION="main"

bash rootfs/build_rootfs.sh
```

产物：

- `build/rootfs/rootfs.tar.zst` — zstd 压缩的根文件系统
- `build/rootfs/rootfs_manifest.json` — 校验清单（关键文件 + sha256）

> **说明**：DSH 启动入口已修正为 `dsh web`（真实 DSH 是 TypeScript 单仓，Web 模式入口为
> `apps/cli/src/bin.ts`，见 `rootfs/start_dsh.sh`）。构建需 Node ≥ 24.9 与 pnpm（见 `rootfs/build_rootfs.sh`），
> RootFS 构建请在原生 arm64 Linux（如 GitHub `ubuntu-24.04-arm` runner）上执行。

## 2. 打包资产

```bash
# proot-rs arm64 静态二进制（GPLv2）需指定下载地址与 SHA256 校验值
export PROOT_RS_URL="https://github.com/proot-me/proot-rs/releases/download/v<版本>/proot-rs-aarch64"
export PROOT_RS_SHA256="<实际 sha256>"

bash packaging/package_assets.sh
```

产物：

- `app/src/main/jniLibs/arm64-v8a/libproot_rs.so` — proot-rs 二进制（原生库形式，规避 Android 10+ 执行限制）
- `app/src/main/assets/rootfs.zst.000` … — RootFS 分卷（默认 100MB/卷）
- `app/src/main/assets/rootfs_manifest.json` — 校验清单

## 3. 编译并签名 APK

```bash
# 配置 Android SDK 路径（或写入 local.properties：sdk.dir=/path/to/sdk）
# 配置签名（或跳过签名，仅产出未签名包用于本地调试）
export KEYSTORE="/path/to/release.keystore"
export KEYSTORE_ALIAS="fishadopt"
export STORE_PASS="<密码>"

bash packaging/sign_and_build.sh
```

产物：

- `app/build/outputs/apk/release/fishadopt-release.apk`（签名）或 `fishadopt-unsigned.apk`（未签名）

## 4. 端口配置说明

- 应用默认 DSH 端口为 **3080**（真实 DSH web 默认端口，见 `SettingsRepository` 与 `ServiceStateHolder`）。
- 该值必须与所捆绑 DSH 版本的默认监听端口一致；`start_dsh.sh` 会透传 `DSH_PORT` 环境变量。
- 如需修改，请在设置页调整端口，并确保 DSH 读取 `DSH_PORT`/`PORT` 环境变量。

## 5. 常见问题

- **assets 缺失**：未执行 `package_assets.sh` 时应用可编译，但环境停留在"未初始化"，主界面显示"准备环境"后提示未找到分卷。
- **首次构建失败**：首版 release 关闭了 R8 混淆，若开启后遇到反射/WebView 问题，先回退 `isMinifyEnabled=false`。
- **机型兼容**：容器启动失败的机型需在日志中输出可定位原因，界面提示"当前机型系统策略不兼容"（而非笼统"启动失败"）。
