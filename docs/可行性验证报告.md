## 二、关键事实（直接影响 APP 实现）

1. **默认端口是 3080，不是 51145**。源码 `config-schema.spec.ts` 明确 `Schema.number().default(3080)`。
2. **端口可配**：`dsh web --port <port>`（`--port 0` 让系统分配）。
3. **必须加 `--no-open`**：否则 `dsh web` 会尝试打开浏览器（容器内无浏览器）。
4. **带 token 认证**：启动后 stdout 打印 `dsh web: http://127.0.0.1:3080/?token=<token>`。
   WebView 必须用**带 token 的 URL** 加载；token 是访问凭据，日志需脱敏。
5. **构建需要 git 仓库**：`pnpm build` 内部执行 `git rev-parse HEAD`（打版本戳），
   因此必须用 `git clone`（不能是裸 tarball）；`--depth 1` 浅克隆即可满足。
6. **`build:lib:client` 单独跑会失败**：它依赖"contracts 先生成"这一步，正确命令是完整的 `pnpm build`。

## 三、修正后的技术路线（已验证可行）

```
Debian arm64 RootFS
  ├─ 自装 Node 24 (arm64 tarball)          # Debian 自带 node 太旧
  ├─ 装 pnpm (npm install -g pnpm@11.28.5)
  ├─ git clone deepseek-harness (master)   # 必须 git clone，构建要 commit hash
  ├─ pnpm install                          # 拉到 linux-arm64 预编译原生模块
  ├─ pnpm build                            # 完整 build（157s，勿单独跑 build:lib:client）
  └─ dsh web --port <port> --no-open       # headless 起服务，打印带 token 的地址
        ↑
  外壳解析 stdout 里的 token → WebView 加载带 token 的 URL
```

## 四、代价与风险（即使可行）

- **APK 体积大**：node_modules 2.13GB + Node 24 + DSH 源码，RootFS 压缩后预计仍 **1GB 级别**。
- **RAM 要求高**：Node 24 + 完整 DSH 运行时，6GB 内存手机偏紧。
- **冷启动**：proot 内起 Node 24 + 大应用，可能超 PRD 的 60 秒指标。
- **token 机制**：APP 需新增「解析 stdout 的 token → 加载带 token URL」逻辑，PRD 未覆盖。

## 五、APP 侧需要补的改动（据此定稿）

1. `start_dsh.sh`：已改为 `dsh web --port "$DSH_PORT" --no-open`（✅ 已更新）。
2. 端口默认值：APP 的 `DEFAULT_DSH_PORT` 从 51145 改为 **3080**。
3. `ProotProcessManager`：解析 stdout 的 `dsh web: http://...?token=...` 行，提取带 token 的 URL。
4. `ChatScreen`/WebView：加载带 token 的 URL（而非裸 `http://127.0.0.1:port/`）。
5. `SensitiveMasker`：token（`?token=` 特征）纳入脱敏。

## 六、结论

**「手机 proot 跑官方 DSH Web 版」确认可行**，且原生模块免交叉编译（有 arm64 预编译）。
代价是体积大（GB 级）、内存高、需处理 token 认证与 `--no-open`，且构建必须在 arm64 Linux
（原生或 qemu）上做完整 `pnpm build`。这是上游技术现实，非封装层能绕过，但都在可工程化范围内。
